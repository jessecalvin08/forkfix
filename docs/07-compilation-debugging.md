# Policy compilation: debugging record

Date: September 14, 2026. This is an implementation record, not a claim that the full hackathon product is complete.

## Outcome

A real POST to the running `http://127.0.0.1:8000/api/policies/compile` endpoint successfully returned a policy generated by `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` through Nebius Token Factory. The response reported `status: compiled`, `response_mode: json_schema`, and 12 rules: 9 generated rules plus 3 mandatory local guard rules. The test used the dashboard's synthetic default policy, not a private repository or real secrets.

This proves that account authentication, the selected model, the request format, response parsing, local shape validation, and the running API work together for this input. It does not prove universal model reliability, correct interpretation of every policy, or safe execution of an agent.

## Confirmed causes

1. **Malformed request, HTTP 422.** A previous change sent the raw schema directly as `response_format.json_schema`. The provider explicitly reported missing `response_format.json_schema.name` and `response_format.json_schema.schema`. Restoring a wrapper containing `name`, `schema`, and `strict` corrected that request-contract failure.
2. **Malformed model configuration, HTTP 404.** The local line was `NEBIUS_MODEL=NEBIUS_MODEL=nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`. The provider interpreted the second `NEBIUS_MODEL=` as part of the model identifier. The line now contains the assignment only once. The API key was not changed or printed.
3. **Misleading error handling.** Unrelated provider errors were all presented as a possible JSON-schema support problem. Earlier passing tests used mocked responses and did not verify the outgoing request contract.
4. **Misleading screen state.** The UI could say Validated and show unrelated sample success metrics even when live compilation failed. A compiled policy could also replace the policy shown alongside old traces without rerunning them.

Both direct and frontend-proxied health endpoints responded successfully during diagnosis. A broken Vite proxy was not established as the cause. Model-listing success was authentication evidence, not successful policy generation.

## Changes made

- Restored the named JSON-schema wrapper and included the schema in the compiler prompt.
- Limited each compiler request to 4,096 output tokens, a 60-second client timeout, and zero automatic SDK retries. Removed the broad retry in another output mode on arbitrary HTTP 400 errors.
- Required explicit generated fields, known tools, nonempty rule/path lists, unique IDs, and version `1`. Unexpected fields are rejected instead of silently ignored; missing paths no longer default to all paths for model output.
- Prevented generated rules with reserved IDs from replacing canonical local guards.
- Added an early local error for a repeated `NEBIUS_MODEL=` assignment.
- Classified provider HTTP errors, timeouts, connection failures, and unexpected errors without returning or logging raw provider bodies, exception messages, or credentials.
- Separated generated drafts from the sample comparison. Drafts need review; editing their source text marks them out of date. Error notices are visibly errors. Actual coding-task completion says Not tested.

## Verification performed

- One successful real compile through the running backend after correcting both confirmed causes. Earlier bounded diagnostic attempts produced the documented HTTP 422 and HTTP 404 failures.
- `backend/.venv/Scripts/python.exe -m pytest -q`: **44 passed**, with 2 dependency deprecation warnings. These are offline tests, not additional live generations.
- Frontend `npm run build`: TypeScript and Vite production build passed.
- Direct and frontend-proxied `/api/health`: both responded successfully.
- `git check-ignore backend/.env`: confirmed the private configuration remains ignored.

No private key, real secret file, or private repository content was sent as model input. No sandbox, robot, external collector, real agent tool execution, or actual repository repair was run. The successful live call consumed model usage; the remaining balance was not checked.

## Important limitation discovered in the successful draft

The initial successful model response used an unsuitable `run_tests` target. A later draft used `*`, which would have permitted every test target. The evaluator also allowed nested `.env`/`.git` paths and `..` path escapes because it treated path strings too literally.

These observations demonstrate why passing a JSON schema is not proof of a correct policy. The evaluator now rejects absolute/traversal paths, protects nested `.env` and `.git` paths, and enforces `run_tests` as exactly `pytest` even if a malformed policy bypasses generation-time validation. The already-displayed draft is still a draft, not applied to any execution environment. Human review remains required; do not claim useful work completed.

## Local generated-draft validation

The dashboard now exposes **Test generated draft locally** after a draft has been generated. It sends the in-memory draft to the local `POST /api/policies/validate` endpoint. This does not call Token Factory, spend model credits, or interact with files, commands, networks, or an agent.

When this record was written, the validator evaluated 18 fixed, synthetic tool-call records for the included RuleBranch scenario (on September 19, 2026 it grew to 23; see `STATUS.md`):

- 5 permitted-work checks: read `README.md`, read `src/`, read `tests/`, write within `src/`, and run the exact `pytest` capability.
- 13 boundary checks: root and nested `.env`, root and nested `.git`, private keys, network egress, deletion, writes outside `src/`, read/write traversal, an unapproved test target, a missing target, and an unknown tool.

Each result includes the expected decision, actual decision, and matched rule ID (or deny-by-default). A passing policy returns **18/18**. The known-correct test policy returned 18/18 through the running local API on September 14, and the regression suite also verifies both passing and deliberately failing policies.

This result proves only that the deterministic evaluator makes the expected decisions for these 18 records. It is not sandbox evidence, does not show that an agent completed useful work, and does not make the fixed Baseline/Repair sample into evidence from the generated draft. Actual execution remains a later milestone.

## What Jesse should do next

1. Refresh the local dashboard if the new button is not visible. No new API key or configuration change is needed.
2. For the draft already shown in the browser, select **Test generated draft locally**. It is free and local. Do not select Compile again merely to run this check.
3. Review the detailed results. **18/18 passed** means the draft matches the fixed scenario matrix; any lower count identifies exactly which expected decision failed.
4. Keep the sample Baseline/Repair panels separate. They remain scripted examples and do not change when the generated draft is tested.
5. After a human approval control is added, the next major milestone is controlled execution in a Nebius Sandbox.

Do not repeatedly click Compile after an error. The new message distinguishes provider status, connection, timeout, configuration, and invalid output. Preserve the message without exposing `.env` or API keys.
